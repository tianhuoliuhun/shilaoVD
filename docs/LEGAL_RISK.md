# 法律风险自查（工程视角）

> ⚠️ 本文是工程视角的风险梳理，**不构成法律意见**。涉及实际分发与使用，请咨询执业律师。

## 一、已确认的风险点（以代码为准）

| # | 风险 | 依据（代码 / 文档） | 当前状态 |
|---|---|---|---|
| 1 | 视频被暂存在本地 | 有预加载（`PreloadManager`，每条约 1MB）和缓存（`ProxyVideoCacheManager`，上限 128MB） | ✅ 已处理：缓存移到应用私有目录，退出时清空；README 已改为准确描述 |
| 2 | README 的「不缓存」声明与实际行为不符 | 原 README 写「不存储、不缓存」 | ✅ 已修正 |

## 二、已确认不存在的功能（降低风险的事实）

- 没有下载、保存、导出、分享视频的功能（已检索代码中的 `download`、`下载`、`分享`、`保存到`、`导出`）。
- 没有登录态：只使用游客身份的 `ttwid` Cookie，不读取、不注入任何用户账号。
- 没有广告、付费、会员功能。

## 三、建议的下一步（按优先级）

1. **咨询律师**：重点评估第 3、4 项。这两项决定是否可以公开分发，工程上无法替代判断。
2. **收窄分发**：如果律师认为风险较高，可以只保留自用版本，不在 Releases 公开发布。
3. **保持非商业性**：不加广告、付费、会员。商业化会显著放大风险。
4. **建立下架渠道**：在 README 中写明联系方式，收到权利方的删除请求时能及时处理。
5. **决定是否恢复免责声明**：首次启动时弹出一次即可，文案由律师确认。

## 四、本次改动（分支 `feat/douyin-fallback-legal`）

- `ProxyVideoCacheManager`：缓存目录改为应用私有目录；新增 `clearAll`，退出时清空并关闭本地代理。
- `FeedActivity.onDestroy`：应用真正退出时（`isFinishing`）调用清空。
- `README.md`：修正「版权与使用声明」中与实际行为不符的描述。
- `DouyinApi` / `FeedSourcePicker`：内容源失败时自动切换到其它源，并冷却 10 分钟（见下一节）。
